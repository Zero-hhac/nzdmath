## Step 02：活动 / 资讯 / 资源列表（全量返回）

这三个模块的公开列表实现很直接：**只查 `status=1` 的已发布数据，全量返回**（数据量可控，前端一次性拿全，不在后端做分页）。

**文件**：`internal/service/event_service.go`

```go
func (s *EventService) ListEvents() ([]model.Event, error) {
	var events []model.Event
	err := s.db.Select("id, title, summary, category, location, start_time, end_time, cover_url, is_featured, status, created_at, content").
		Where("status = ?", 1).
		Order("id desc").
		Find(&events).Error
	if err != nil {
		return nil, err
	}
	return events, nil
}

func (s *EventService) GetEventByID(id uint64) (*model.Event, error) {
	var event model.Event
	err := s.db.Where("id = ? AND status = ?", id, 1).First(&event).Error
	if err != nil {
		if errors.Is(err, gorm.ErrRecordNotFound) {
			return nil, errors.New("活动不存在")
		}
		return nil, err
	}
	return &event, nil
}
```

资讯（`news_service.go`）几乎一样，区别是排序用 `published_at desc, id desc`（按发布时间倒序）。资源（`resource_service.go`）的列表返回 `dto.ResourceListItem`（精简字段，不含磁盘路径），详情返回 `dto.ResourceDetail`。

**关键点**：
- 所有公开查询都带 `status = 1` 条件，草稿/下架内容不可见
- `Select(...)` 显式列出返回字段，避免把大字段（如 `content` 之外的冗余）或敏感字段带出去
- 详情查不到时统一转成业务错误（"活动不存在"），而不是把 `gorm.ErrRecordNotFound` 直接抛给前端

**验证**：

```bash
curl http://localhost:8080/api/v1/events
curl http://localhost:8080/api/v1/events/1
curl http://localhost:8080/api/v1/news
curl http://localhost:8080/api/v1/resources
curl http://localhost:8080/api/v1/resources/1
```

## Step 03：作品档案（筛选 + 分页）

作品是唯一在公开列表做了筛选和分页的模块，因为字段多、筛选维度多。

**文件**：`internal/service/showcase_service.go`

```go
func (s *ShowcaseService) ListShowcases(field, competition, keyword string, page, pageSize int) ([]model.Showcase, int64, error) {
	var showcases []model.Showcase
	var total int64

	query := s.db.Model(&model.Showcase{}).Where("status = ?", 1)

	if field != "" {
		query = query.Where("field = ?", field)
	}
	if competition != "" {
		query = query.Where("competition LIKE ?", "%"+competition+"%")
	}
	if keyword != "" {
		query = query.Where("title LIKE ? OR summary LIKE ?", "%"+keyword+"%", "%"+keyword+"%")
	}

	if err := query.Count(&total).Error; err != nil {
		return nil, 0, err
	}

	if page <= 0 {
		page = 1
	}
	if pageSize <= 0 {
		pageSize = 10
	}
	offset := (page - 1) * pageSize

	if err := query.Order("id desc").Offset(offset).Limit(pageSize).Find(&showcases).Error; err != nil {
		return nil, 0, err
	}
	return showcases, total, nil
}
```

**关键点**：
- `field` 精确匹配，`competition` 模糊匹配，`keyword` 对标题和简介模糊搜索
- 分页参数做了兜底（`page<1` 归 1，`pageSize<1` 归 10）
- 详情访问时 `view_count` 自增（见 `GetShowcase`）

**验证**：

```bash
curl "http://localhost:8080/api/v1/showcases?field=几何学&page=1&page_size=10"
curl "http://localhost:8080/api/v1/showcases?keyword=分形"
curl http://localhost:8080/api/v1/showcases/1
```

## Step 04：资源下载与下载日志

**文件**：`internal/service/resource_service.go`

下载前把 `/uploads/` 前缀的路径转成本地磁盘路径，并让下载计数自增：

```go
func (s *ResourceService) GetForDownload(id uint64) (*model.Resource, error) {
	var resource model.Resource
	if err := s.db.Where("id = ? AND status = ?", id, 1).First(&resource).Error; err != nil {
		return nil, err
	}
	if strings.HasPrefix(resource.FilePath, "/uploads/") {
		uploadBase := config.GlobalConfig.Storage.UploadDir
		if uploadBase == "" {
			uploadBase = "./storage/uploads"
		}
		resource.FilePath = filepath.Join(uploadBase, strings.TrimPrefix(resource.FilePath, "/uploads/"))
	}
	s.db.Model(&model.Resource{}).Where("id = ?", id).
		UpdateColumn("download_count", gorm.Expr("download_count + 1"))
	return &resource, nil
}
```

下载记录写入 `download_logs` 表，供「我的下载」查询：

```go
func (s *ResourceService) RecordDownload(userID uint, resourceID uint, ip, userAgent string) error {
	log := model.DownloadLog{
		UserID:     userID,
		ResourceID: resourceID,
		IP:         ip,
		UserAgent:  userAgent,
	}
	return s.db.Create(&log).Error
}
```

**关键点**：
- 数据库里存的是磁盘路径，但公开给前端的始终是 `/uploads/...` URL；下载时再反转成本地路径
- `download_count` 用 `gorm.Expr("download_count + 1")` 原子自增，避免并发下丢计数
- 下载记录带 IP 和 UserAgent，用于统计和审计

## Step 05：首页聚合（版本化缓存）

**文件**：`internal/service/homepage_service.go`

首页一次请求返回多块数据：最近活动、精选活动、最近资讯、精选资讯、精选资源、热门作品。

```go
type HomepageData struct {
	RecentEvents      []model.Event    `json:"recent_events"`
	FeaturedEvents    []model.Event    `json:"featured_events"`
	RecentNews        []model.News     `json:"recent_news"`
	FeaturedNews      []model.News     `json:"featured_news"`
	FeaturedResources []model.Resource `json:"featured_resources"`
	RecentShowcases   []model.Showcase `json:"recent_showcases"`
	UpdatedAt         time.Time        `json:"updated_at"`
}
```

核心是**版本化缓存**，配合后台「主动失效」：

```go
func (s *HomepageService) Get() (*HomepageData, error) {
	ctx := context.Background()
	version := s.cache.GetInt(ctx, "cache:homepage:version")
	cacheKey := "cache:homepage:v" + intToStr(version)

	var cached HomepageData
	if s.cache.Get(ctx, cacheKey, &cached) {
		return &cached, nil
	}

	data := &HomepageData{UpdatedAt: time.Now()}
	// 用 6 个 goroutine 并发查询 6 块数据（waitGroup 等待）
	// ...
	s.cache.Set(ctx, cacheKey, data, time.Duration(consts.CacheTTLHomepage)*time.Second)
	return data, nil
}

func (s *HomepageService) Invalidate() {
	s.cache.Incr(context.Background(), "cache:homepage:version")
}
```

**关键点**：
- 缓存 key 是 `cache:homepage:v{version}`，`version` 存在 Redis 的 `cache:homepage:version`
- 后台内容变更后调用 `Invalidate()`，只需把 version +1，旧缓存自然失效（而不是逐个删 key）
- TTL 是 `consts.CacheTTLHomepage`（300 秒）
- 6 块数据用 goroutine + `sync.WaitGroup` 并发查库，降低首页延迟

## Step 07：流量埋点（PV / UV / DAU）

**文件**：`internal/router/router.go` 的 `/active/track` 路由

前端每次进入页面时调这个接口，后端用 Redis 统计 PV / UV / DAU：

```go
public.POST("/active/track", func(c *gin.Context) {
	today := time.Now().Format("2006-01-02")
	ctx := c.Request.Context()

	// 1. PV：简单的计数器
	pvKey := "dau:pv:" + today
	rdb.Incr(ctx, pvKey)
	rdb.Expire(ctx, pvKey, 48*time.Hour)
	rdb.Incr(ctx, "dau:pv:all")

	// 2. UV：IP 独立访客，用 HyperLogLog 去重
	clientIP := c.ClientIP()
	if clientIP != "" {
		uvKey := "dau:ip:" + today
		rdb.PFAdd(ctx, uvKey, clientIP)
		rdb.Expire(ctx, uvKey, 48*time.Hour)
		rdb.PFAdd(ctx, "dau:ip:all", clientIP)
	}

	// 3. DAU：登录会员独立活跃数（解析 token 拿到 userID）
	// ... 用 rdb.PFAdd(ctx, "dau:user:"+today, userID)

	response.Success(c, nil)
})
```

**关键点**：
- PV 用 `Incr` 计数器；UV/DAU 用 `PFAdd`（HyperLogLog，内存极省，适合去重计数）
- 按天分 key，TTL 48 小时；另有 `:all` 累计 key
- 这些数据最终在后台 dashboard 展示，并由 `daily_metrics` 表归档（见第六阶段）

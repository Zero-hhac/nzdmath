# 第七阶段：容器化部署

本阶段目标：用 Docker Compose 一键拉起 MySQL + Redis + Backend + Frontend(Nginx) 四个服务，通过 Nginx 统一前后端入口。

> 对应文件：根目录 `docker-compose.yml`、`backend/Dockerfile`、`frontend/Dockerfile`、`frontend/nginx.conf`、`backend/configs/config.docker.yaml`、`.env.example`

---

## Step 01：整体架构

```
浏览器 :80
   │
   ▼
┌─────────────┐   /api/ 与 /uploads/ 反向代理   ┌──────────┐
│  frontend    │ ──────────────────────────────▶ │ backend  │
│  (Nginx)     │                                 │  :8080   │
└─────────────┘                                 └────┬─────┘
                                                    │
                                      ┌─────────────┴─────────────┐
                                      ▼                           ▼
                                 ┌─────────┐                ┌─────────┐
                                 │  mysql  │                │  redis  │
                                 │ :3306(内)│                │ :6379(内)│
                                 └─────────┘                └─────────┘
```

- 对外只暴露两个端口：`80`（前端/Nginx）和用于本机调试的 `3307`/`6380`（映射到容器内的 MySQL/Redis）
- 容器之间通过服务名通信（`backend`、`mysql`、`redis`），不走 `127.0.0.1`

## Step 02：后端 Dockerfile（多阶段构建）

**文件**：`backend/Dockerfile`

```dockerfile
FROM golang:1.26-alpine AS builder

WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o /out/server ./cmd/server

FROM alpine:latest

RUN apk add --no-cache tzdata ca-certificates && \
    cp /usr/share/zoneinfo/Asia/Shanghai /etc/localtime && \
    echo "Asia/Shanghai" > /etc/timezone

WORKDIR /app
COPY --from=builder /out/server .
COPY configs ./configs
RUN mkdir -p /app/storage/uploads /app/storage/logs

EXPOSE 8080
CMD ["./server"]
```

**关键点**：
- `CGO_ENABLED=0` + `GOOS=linux` 交叉编译出纯静态二进制，最终镜像用 `alpine` 极简运行
- 运行阶段装 `tzdata` 并设为 `Asia/Shanghai`，保证 `time.Time` 时区正确
- 上传目录 `/app/storage/uploads` 在运行阶段预创建（并会被 compose 挂载卷覆盖）

## Step 03：Docker Compose 编排

**文件**：根目录 `docker-compose.yml`（关键部分）

```yaml
services:
  mysql:
    image: mysql:8.0
    container_name: math-top-mysql
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_PASSWORD:?set MYSQL_PASSWORD in .env}
      MYSQL_DATABASE: math_top
    volumes:
      - mysql_data:/var/lib/mysql
    ports:
      - "3307:3306"          # 本机调试用，对外映射到 3307
    healthcheck:
      test: ["CMD-SHELL", "mysqladmin ping -h localhost -u root -p$${MYSQL_PASSWORD}"]
      interval: 5s
      timeout: 5s
      retries: 10
    networks:
      - math-top-network

  redis:
    image: redis:7-alpine
    container_name: math-top-redis
    volumes:
      - redis_data:/data
    ports:
      - "6380:6379"
    networks:
      - math-top-network

  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile
    container_name: math-top-backend
    depends_on:
      mysql:
        condition: service_healthy   # 等 MySQL 健康检查通过再启动
      redis:
        condition: service_started
    environment:
      - APP_ENV=docker
      - MYSQL_PASSWORD=${MYSQL_PASSWORD:?set MYSQL_PASSWORD in .env}
      - JWT_SECRET=${JWT_SECRET:?set JWT_SECRET in .env}
      - ADMIN_INITIAL_PASSWORD=${ADMIN_INITIAL_PASSWORD:-}
    volumes:
      - ./backend/storage/uploads:/app/storage/uploads
    expose:
      - "8080"
    networks:
      - math-top-network

  frontend:
    build:
      context: ./frontend
      dockerfile: Dockerfile
    container_name: math-top-nginx
    ports:
      - "80:80"
    depends_on:
      - backend
    networks:
      - math-top-network

volumes:
  mysql_data:
  redis_data:

networks:
  math-top-network:
    driver: bridge
```

**关键点**：
- `${MYSQL_PASSWORD:?...}` 语法：`.env` 里没定义该变量时 compose 会直接报错退出，避免用默认弱密码上线
- `depends_on` 用 `condition: service_healthy` 让 backend 等 MySQL **真正就绪**再启动，而不是只等容器创建
- backend 不对外映射 8080，只 `expose` 到内部网络，由 Nginx 反代（更安全）
- MySQL/Redis 都挂了命名卷，容器重建数据不丢

## Step 04：容器环境配置

**文件**：`backend/configs/config.docker.yaml`

容器里 MySQL/Redis 的主机名是服务名，密码和 JWT 密钥从环境变量注入：

```yaml
app:
  name: math-top-backend
  port: "8080"
  mode: debug

mysql:
  host: mysql          # 服务名，不是 127.0.0.1
  port: 3306
  user: root
  password: ""         # 通过 MYSQL_PASSWORD 环境变量注入
  dbname: math_top

redis:
  host: redis          # 服务名
  port: 6379
  password: ""
  db: 0

jwt:
  secret: ""           # 通过 JWT_SECRET 环境变量注入
  expire_hours: 24

storage:
  upload_dir: ./storage/uploads
```

配合 `config.go` 里的逻辑，`APP_ENV=docker` 时 viper 会读 `config.docker.yaml`：

```go
viper.SetConfigName("config")
if env := os.Getenv("APP_ENV"); env != "" {
	viper.SetConfigName("config." + env)  // → config.docker
}
```

`viper.BindEnv` 让环境变量覆盖 yaml 里的空值：

```go
viper.BindEnv("mysql.password", "MYSQL_PASSWORD")
viper.BindEnv("jwt.secret", "JWT_SECRET")
viper.BindEnv("app.mode", "APP_MODE")
```

## Step 05：前端 Nginx 配置

**文件**：`frontend/nginx.conf`、`frontend/Dockerfile`

前端先用 Node 构建，再把 `dist` 塞进 Nginx 镜像：

```dockerfile
FROM node:22-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

Nginx 核心三件事：

```nginx
# 1. 前端 SPA：刷新不 404
location / {
    root /usr/share/nginx/html;
    index index.html index.htm;
    try_files $uri $uri/ /index.html;
}

# 2. 后端 API 反向代理
location /api/ {
    proxy_pass http://backend:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 50m;   # 大文件上传
    proxy_connect_timeout 60s;
    proxy_send_timeout 60s;
    proxy_read_timeout 60s;
}

# 3. 上传文件代理（资源/头像/聊天文件）
location /uploads/ {
    proxy_pass http://backend:8080;
    expires 7d;
}
```

**关键点**：
- `/api/` 和 `/uploads/` 都反代到 backend，因为上传文件是由后端 `r.Static("/uploads", ...)` 托管的
- `client_max_body_size 50m` 与后端 50MB 上传上限对齐
- SPA 用 `try_files ... /index.html` 兜底，前端路由刷新不会 404

## Step 06：敏感配置管理（.env）

**文件**：`.env.example`（可提交到 Git）

```bash
MYSQL_PASSWORD=change-me-strong-db-password
JWT_SECRET=change-me-to-a-long-random-secret
ADMIN_INITIAL_PASSWORD=change-me-admin-password
```

**启动步骤**：

```bash
# 1. 复制环境变量模板并填写真实值
cp .env.example .env   # 编辑 .env 填入强密码和长随机 JWT 密钥

# 2. 一键构建并启动（后台运行）
docker compose up --build -d

# 3. 查看日志确认四个服务都起来
docker compose logs -f

# 4. 访问
# 门户/后台：http://localhost
# 后端接口：http://localhost/api/v1/...
```

**关键点**：
- `.env` 绝不能提交到 Git（真实密码/JWT 密钥在这里）
- `ADMIN_INITIAL_PASSWORD` 生产环境**必须设置**：`admin_service.go` 里当 `mode: release` 且未设置该变量时会拒绝创建默认管理员（安全兜底，见第三阶段）

## Step 07：验证清单

```bash
# 健康检查（走 Nginx 反代）
curl http://localhost/health
# 预期：{"code":200,"msg":"success","data":{"status":"ok"}}

# API 反代
curl http://localhost/api/v1/home
# 预期：返回首页聚合数据

# 前端页面
# 浏览器打开 http://localhost，应看到 React 页面
# 访问前端子路由（如 /events）刷新不应 404

# 上传文件（头像/资源）后应能通过 http://localhost/uploads/... 访问
```

**如果出错**：
- `connection refused`：backend 可能没等 MySQL 就绪就启动，检查 `depends_on.condition: service_healthy` 和 mysql healthcheck 是否配置正确
- 404：检查 Nginx `try_files` 和 `/api/` 反代路径
- 上传文件 413：检查 Nginx `client_max_body_size` 是否 ≥ 后端限制

## 第七阶段验收标准

- [ ] `docker compose up --build -d` 能一键拉起 4 个服务
- [ ] MySQL 数据挂 `mysql_data` 卷，容器重建后数据不丢
- [ ] backend 通过 `APP_ENV=docker` 读 `config.docker.yaml`，用服务名连上 MySQL/Redis
- [ ] `curl http://localhost/health` 返回正常（经 Nginx 反代）
- [ ] `curl http://localhost/api/v1/home` 返回首页数据
- [ ] 前端页面正常打开，SPA 路由刷新不 404
- [ ] 上传文件后可经 `http://localhost/uploads/...` 访问
- [ ] `.env` 管理敏感配置，未提交到 Git；`MYSQL_PASSWORD`/`JWT_SECRET` 未设置时 compose 拒绝启动

**项目完成！** 🎉

## 后续可扩展方向

1. **HTTPS**：给 Nginx 配 SSL 证书（Let's Encrypt / 阿里云证书）
2. **CI/CD**：GitHub Actions 自动构建镜像、推送到镜像仓库、服务器自动拉取部署
3. **监控**：接入 Prometheus + Grafana 观察服务指标
4. **日志收集**：ELK 或 Loki 收集分析日志
5. **对象存储**：上传文件迁移到阿里云 OSS / AWS S3，减小服务器磁盘压力
6. **数据库优化**：读写分离、连接池调优、慢查询索引优化
7. **消息队列**：用 RabbitMQ/Kafka 处理异步任务（邮件通知、消息推送）

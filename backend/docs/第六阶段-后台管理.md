# 第六阶段：后台管理

本阶段目标：实现管理员 dashboard、各模块 CRUD、用户/评论/聊天管理，以及首页缓存失效。

> 对应代码：`internal/service/admin_service.go`、`admin_event_service.go`、`admin_news_service.go`、`admin_resource_service.go`、`admin_showcase_service.go`、`admin_user_service.go`，路由在 `internal/router/router.go` 的 `registerAdminRoutes`

## Step 01：后台路由结构

后台路由分两层：登录/登出在鉴权之外，其余接口加双中间件。

```go
admin := r.Group("/api/v1/admin")
adminLimit := middleware.RateLimitMiddleware(rdb, 20, time.Minute)
admin.POST("/auth/login", adminLimit, adminHandler.Login)
admin.POST("/auth/logout", adminHandler.Logout)

auth := admin.Group("")
auth.Use(middleware.AdminJWTAuthMiddleware(rdb))  // 先验 token（admin_token: 前缀）
auth.Use(middleware.AdminAuthMiddleware())          // 再验角色是 admin/super_admin
{
	auth.GET("/dashboard", adminHandler.Dashboard)
	auth.POST("/homepage/invalidate", ...)

	// 活动 / 资讯 / 资源 / 作品 的 CRUD
	// 用户 / 评论 / 聊天 管理
}
```

**关键点**：
- 登录/登出必须在鉴权中间件**之外**，否则管理员还没拿到 token 就被拦
- 中间件顺序固定：先 `AdminJWTAuthMiddleware`（身份），后 `AdminAuthMiddleware`（角色）
- 登录接口限流 20 次/分钟

## Step 02：Dashboard 数据看板

**文件**：`internal/service/admin_service.go` 的 `GetDashboard`

Dashboard 一次返回多组统计：

```go
type AdminDashboardResponse struct {
	Counts        DashboardCounts   `json:"counts"`          // 各模块总数
	TodayNew      DashboardTodayNew `json:"today_new"`       // 今日新增
	Trend         DashboardTrend    `json:"trend_7days"`     // 7 天内容发布趋势
	TodayActivity TodayActivity     `json:"today_activity"`  // 今日 PV/UV/DAU
	Activity      ActivityTrend     `json:"activity_trend"`  // 7 天流量趋势
	TotalActivity TotalActivity     `json:"total_activity"`  // 累计 PV/UV
}
```

核心逻辑：

```go
func (s *AdminService) GetDashboard() (*dto.AdminDashboardResponse, error) {
	resp := &dto.AdminDashboardResponse{ /* ... 初始化空切片 ... */ }

	// 1. 各模块总数
	s.db.Model(&model.User{}).Count(&resp.Counts.Users)
	s.db.Model(&model.Event{}).Count(&resp.Counts.Events)
	s.db.Model(&model.News{}).Count(&resp.Counts.News)
	s.db.Model(&model.Resource{}).Count(&resp.Counts.Resources)
	s.db.Model(&model.Showcase{}).Count(&resp.Counts.Showcases)

	// 2. 今日新增（events/news）
	// 3. 7 天内容发布趋势（DATE(created_at) GROUP BY）
	// 4. 同步历史流量指标（syncDailyMetrics）
	// 5. 今日实时 PV/UV/DAU（读 Redis）
	// 6. 7 天流量趋势（历史归档 + 今日实时合并）
}
```

**流量指标归档**（`syncDailyMetrics`）是关键设计：当天数据实时在 Redis（`dau:pv:*` 等），次日由 dashboard 调用时把前 6 天的 Redis 数据归档进 `daily_metrics` 表，然后删除对应 Redis key 释放内存：

```go
func (s *AdminService) syncDailyMetrics(ctx context.Context) {
	now := time.Now()
	for i := 6; i >= 1; i-- {
		dStr := now.AddDate(0, 0, -i).Format("2006-01-02")
		// 若 daily_metrics 已有该日期则跳过
		// 否则从 Redis 读 pv/uv/dau，写入 MySQL，再删 Redis key
	}
}
```

**关键点**：
- 今日流量看 Redis（实时），历史流量看 MySQL（归档），两边在 7 天趋势里拼起来
- UV/DAU 用 Redis HyperLogLog（`PFCount`）近似去重统计

## Step 03：内容模块 CRUD

活动/资讯/资源/作品四个模块的后台接口结构一致（以活动为例）：

```go
auth.GET("/events", adminEventHandler.List)          // 分页 + 状态筛选 + 关键字
auth.GET("/events/:id", adminEventHandler.Detail)
auth.POST("/events", adminEventHandler.Create)
auth.PUT("/events/:id", adminEventHandler.Update)
auth.DELETE("/events/:id", adminEventHandler.Delete)
auth.PATCH("/events/:id/feature", adminEventHandler.ToggleFeature)  // 切换首页推荐
```

创建活动的 DTO（`internal/dto/admin_dto.go`）带严格校验：

```go
type AdminCreateEventRequest struct {
	Title      string    `json:"title" binding:"required,min=2,max=150"`
	Summary    string    `json:"summary" binding:"max=255"`
	Content    string    `json:"content"`
	Category   string    `json:"category"`
	Location   string    `json:"location"`
	StartTime  time.Time `json:"start_time" binding:"required"`
	EndTime    time.Time `json:"end_time" binding:"required"`
	CoverURL   string    `json:"cover_url"`
	Status     int       `json:"status" binding:"oneof=0 1"`
	IsFeatured bool      `json:"is_featured"`
}
```

**关键点**：
- `status` 用 `oneof=0 1` 校验（0 草稿 / 1 发布），后台保存草稿前台不可见
- `IsFeatured` 控制是否上首页；`PATCH /feature` 提供单独切换接口
- 资源的创建走文件上传（`auth.POST("/resources", resourceHandler.Upload)`），不是普通 JSON——资源先上传文件再建记录

**验证**（创建后前台应立即可见）：

## Step 04：用户管理

**文件**：`internal/service/admin_user_service.go`

```go
auth.GET("/users", adminUserHandler.List)                       // 分页 + 关键字
auth.PATCH("/users/:id/status", adminUserHandler.SetStatus)     // 禁用/启用
auth.POST("/users/:id/reset-password", adminUserHandler.ResetPassword)  // 重置密码
auth.DELETE("/users/:id", adminUserHandler.Delete)              // 删除用户
```

**关键点**：
- 禁用用户（`status=0`）后，该用户无法登录、无法聊天（`chat_service` 里校验了 `Status != 1`）
- 重置密码由管理员触发，密码重新 bcrypt 加密
- 删除用户走软删除（`users` 表有 `DeletedAt`）

## Step 05：评论与聊天管理

评论管理（`internal/service/comment_service.go`）：

```go
auth.GET("/comments", adminCommentHandler.List)                // 分页 + 目标类型 + 状态筛选
auth.DELETE("/comments/:id", adminCommentHandler.Delete)       // 管理员删任意评论
auth.PATCH("/comments/:id/status", adminCommentHandler.SetStatus)  // 显示/隐藏
```

聊天管理（`internal/service/chat_service.go`）：

```go
auth.GET("/chat/messages", adminChatHandler.List)              // 分页列表
auth.DELETE("/chat/messages/:id", adminChatHandler.Delete)     // 管理员删任意消息
```

**关键点**：
- 管理员删评论/消息不受「只能删自己的」限制（走 `AdminDelete` / `AdminDeleteMessage`）
- 管理员隐藏评论（`status=0`）后，公开列表 `status=1` 条件会自动过滤
- 管理员删聊天消息后，会写 `chat:deleted` 集合，通知在线客户端同步移除

## Step 06：首页缓存失效

后台修改内容后，需要让首页缓存立即刷新：

```go
auth.POST("/homepage/invalidate", func(c *gin.Context) {
	homepageService.Invalidate()
	response.Success(c, nil)
})
```

`Invalidate` 只是把 Redis 里的 `cache:homepage:version` +1（见第四阶段）：

```go
func (s *HomepageService) Invalidate() {
	s.cache.Incr(context.Background(), "cache:homepage:version")
}
```

**关键点**：这是「版本号失效」模式——不改具体缓存 key，只改版本号，下次访问首页时用新版本号拼 key，旧缓存自然不再命中。比逐个删除缓存 key 更简单、更不容易漏。

# 学习路线总览

本文档是 `math-top` 后端项目的索引表，按"基础设施 → 数据 → 鉴权 → 公开接口 → 会员互动 → 后台 → 部署"的顺序，逐层介绍项目的真实实现。

> **使用方式**：先通读本文档建立全局认知，再按编号依次阅读每个阶段的详细说明。每份文档描述的都是当前仓库里**真实存在的代码**，代码片段和文件路径均以 `backend/` 下的实际实现为准。

---

## 项目概览

- **项目名**：math-top（数学爱好者协会全栈应用的后端）
- **Go 模块名**：`math-top`（`backend/go.mod`）
- **技术栈**：Go 1.26 / Gin / GORM / MySQL 8.0 / Redis 7 / Viper / JWT(v5) / bcrypt / `log/slog`
- **服务端口**：`8080`（由 `configs/config.yaml` 的 `app.port` 配置）

## 真实目录结构

```
backend/
├── cmd/server/main.go          # 入口：加载路由引擎 + http.Server 优雅停机
├── configs/
│   ├── config.yaml             # 本地开发配置
│   ├── config.example.yaml     # 配置模板（可提交）
│   └── config.docker.yaml      # 容器环境配置（host 用服务名）
├── internal/
│   ├── config/                 # 配置加载（LoadConfig）+ MySQL/Redis 连接
│   ├── consts/                 # 全局常量（角色/状态/TTL 等）
│   ├── model/                  # 13 张表的 GORM 模型
│   ├── repository/             # 数据访问层（repository.go 聚合 9 个 repo）
│   ├── service/                # 业务逻辑层
│   ├── handler/                # HTTP 处理器层
│   ├── router/                 # 路由引擎（NewEngine + 三组路由注册）
│   ├── middleware/             # CORS / JWT / 管理员鉴权 / 限流
│   ├── response/               # 统一响应封装（Success/Fail/PageSuccess）
│   ├── cache/                  # Redis 缓存统一封装
│   ├── dto/                    # 请求/响应结构体
│   └── utils/                  # JWT 生成与解析
├── storage/uploads/            # 上传文件目录（头像/资源/聊天文件）
├── migrations/                 # 预留 SQL 迁移目录（当前用 AutoMigrate）
├── test/                       # 测试文件
├── Dockerfile                  # 后端多阶段构建
├── docker-compose.yml          # 后端单独编排（占位，实际编排在根目录）
├── go.mod / go.sum
```

> 说明：Docker 编排文件在**仓库根目录** `docker-compose.yml`，统一管理 MySQL / Redis / backend / frontend 四个服务；`backend/docker-compose.yml` 目前为空占位。

## 接口分组概览

所有接口统一挂在 `/api/v1` 前缀下，分为三组：

- **公开接口**（无需登录）：`/home`、`/events`、`/news`、`/resources`、`/showcases`、`/comments`、`/auth/register`、`/auth/login`、`/auth/logout`、`/active/track`
- **会员接口**（需 JWT）：`/profile`、`/user/avatar`、`/member/favorites`、`/member/downloads`、`/comments`、`/chat/*`
- **后台接口**（需管理员 JWT）：`/api/v1/admin/*`，含 dashboard、各模块 CRUD、用户/评论/聊天管理

---

## 统一约定（全项目通用）

- **响应结构**：`{ "code", "msg", "data" }`，成功时 `code=200`、`msg="success"`；分页接口额外返回 `total`、`page`、`pageSize`
- **鉴权**：`Authorization: Bearer <token>`；用户 token 存在 Redis key `token:<token>`，管理员 token 存在 `admin_token:<token>`
- **角色**：`member` / `admin` / `super_admin`（见 `internal/consts/consts.go`）
- **软删除**：users / resources / comments / chat_messages / download_logs 等带 `DeletedAt` 字段，GORM 自动过滤
- **缓存**：统一走 `internal/cache/redis_cache.go` 的 `Cache` 封装，TTL 常量定义在 `consts.go`

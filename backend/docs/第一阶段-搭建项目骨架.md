## Step 01：理解启动入口

**文件**：`cmd/server/main.go`

入口函数只做两件事：用 `router.NewEngine()` 拿到 Gin 引擎，然后挂到 `http.Server` 上并做优雅停机。

```go
func main() {
	r := router.NewEngine()
	srv := &http.Server{Addr: router.Addr(), Handler: r}

	go func() {
		slog.Info("服务启动", "addr", srv.Addr)
		if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			slog.Error("服务异常退出", "err", err)
			os.Exit(1)
		}
	}()

	quit := make(chan os.Signal, 1)
	signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
	<-quit
	slog.Info("收到退出信号，开始关闭服务...")

	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	if err := srv.Shutdown(ctx); err != nil {
		slog.Error("服务关闭超时", "err", err)
		os.Exit(1)
	}
	slog.Info("服务已退出")
}
```

**关键点**：
- 端口来自 `router.Addr()`，即 `":" + config.GlobalConfig.App.Port`
- `http.Server` + `Shutdown` 实现优雅停机：收到 SIGINT/SIGTERM 后等待最多 5 秒处理完在途请求
- 日志统一用标准库 `log/slog`

**验收**：`go run cmd/server/main.go` 启动后终端打印 `服务启动 addr=:8080` 和局域网访问地址。

## Step 02：配置加载（Viper）

**文件**：`internal/config/config.go`

配置结构定义了 `App`、`MySQL`、`Redis`、`JWT`、`Storage` 五个子块：

```go
type Config struct {
	App     AppConfig     `mapstructure:"app"`
	MySQL   MySQLConfig   `mapstructure:"mysql"`
	Redis   RedisConfig   `mapstructure:"redis"`
	JWT     JWTConfig     `mapstructure:"jwt"`
	Storage StorageConfig `mapstructure:"storage"`
}
```

`LoadConfig()` 的核心逻辑：

```go
func LoadConfig() *Config {
	if GlobalConfig != nil {
		return GlobalConfig
	}
	viper.SetConfigName("config")
	if env := os.Getenv("APP_ENV"); env != "" {
		viper.SetConfigName("config." + env)
	}
	viper.SetConfigType("yaml")
	viper.AddConfigPath("./configs")
	viper.AddConfigPath("./internal/config")

	viper.BindEnv("mysql.password", "MYSQL_PASSWORD")
	viper.BindEnv("jwt.secret", "JWT_SECRET")
	viper.BindEnv("app.mode", "APP_MODE")

	if err := viper.ReadInConfig(); err != nil {
		slog.Error("读取配置文件失败", "err", err)
		panic(err)
	}

	var config Config
	if err := viper.Unmarshal(&config); err != nil {
		slog.Error("解析配置文件失败", "err", err)
		panic(err)
	}
	GlobalConfig = &config
	return &config
}
```

**关键点**：
- 全局单例 `GlobalConfig`，多处调用不会重复加载
- 通过环境变量 `APP_ENV` 切换配置：本地读 `config.yaml`，容器里 `APP_ENV=docker` 时读 `config.docker.yaml`
- `viper.BindEnv` 让 `MYSQL_PASSWORD`、`JWT_SECRET`、`APP_MODE` 三个环境变量可以覆盖 yaml 里的值——这是部署时注入敏感配置的关键
- 配置读取失败直接 panic，让问题在启动时暴露

**配置文件**（`configs/config.yaml`，本地开发版）：

```yaml
app:
  name: math-top-backend
  port: "8080"          # 端口用字符串，拼接时方便
  mode: debug            # debug 或 release

mysql:
  host: 127.0.0.1
  port: 3306
  user: root
  password: "123456"     # ← 改成你自己的密码
  dbname: math_top

redis:
  host: 127.0.0.1
  port: 6379
  password: ""
  db: 0

  upload_dir: ./storage/uploads
```

**如果出错**：
- `mapstructure` tag 必须和 yaml key 完全一致
- yaml 缩进用空格，别用 Tab

## Step 03：MySQL 与 Redis 连接

**文件**：`internal/config/mysql.go`、`internal/config/redis.go`

两者都在 `config` 包里，连接失败直接 panic：

```go
// mysql.go
func ConnectMysql() *gorm.DB {
	cfg := GlobalConfig
	if cfg == nil {
		LoadConfig()
		cfg = GlobalConfig
	}
	dsn := fmt.Sprintf("%s:%s@tcp(%s:%d)/%s?charset=utf8mb4&parseTime=True&loc=Local",
		cfg.MySQL.User, cfg.MySQL.Password, cfg.MySQL.Host, cfg.MySQL.Port, cfg.MySQL.DBName)

	db, err := gorm.Open(mysql.Open(dsn), &gorm.Config{})
	if err != nil {
		slog.Error("数据库连接失败", "err", err)
		panic(err)
	}
	slog.Info("数据库连接成功", "host", cfg.MySQL.Host, "db", cfg.MySQL.DBName)
	return db
}
```

```go
// redis.go
func InitRedis() *redis.Client {
	cfg := GlobalConfig
	if cfg == nil {
		LoadConfig()
		cfg = GlobalConfig
	}
	addr := fmt.Sprintf("%s:%d", cfg.Redis.Host, cfg.Redis.Port)
	rdb := redis.NewClient(&redis.Options{
		Addr:     addr,
		Password: cfg.Redis.Password,
		DB:       cfg.Redis.DB,
	})

	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	if _, err := rdb.Ping(ctx).Result(); err != nil {
		slog.Error("Redis 连接失败", "addr", addr, "err", err)
		panic(err)
	}
	slog.Info("Redis 连接成功", "addr", addr)
	return rdb
}
```

**关键点**：
- DSN 里的 `parseTime=True` 让 GORM 把 `time.Time` 正确映射到 `DATETIME`
- Redis 用 5 秒超时的 `Ping` 探活

## Step 04：统一响应封装

**文件**：`internal/response/response.go`

全项目统一返回 `{ code, msg, data }` 结构：

```go
func Success(c *gin.Context, data any) {
	c.JSON(200, gin.H{"code": 200, "msg": "success", "data": data})
}

func Fail(c *gin.Context, code int, msg string) {
	c.JSON(code, gin.H{"code": code, "msg": msg})
}

func PageSuccess(c *gin.Context, data any, total int64, page int, pageSize int) {
	c.JSON(200, gin.H{
		"code": 200, "msg": "success", "data": data,
		"total": total, "page": page, "pageSize": pageSize,
	})
}
```

**关键点**：
- 成功一律 HTTP 200，`code=200`
- 失败时 HTTP 状态码与业务 `code` 一致（如 400、401、403、429、500）
- 分页列表用 `PageSuccess`，`total`/`page`/`pageSize` 是顶层字段，不在 `data` 里
- 字段名是 `msg`，不是 `message`

**验收**：handler 里 `response.Success(c, gin.H{"status": "ok"})` 一行即可返回统一 JSON。

## Step 05：路由引擎与启动流程

**文件**：`internal/router/router.go`

`NewEngine()` 是项目的"装配中心"，完整启动流程都在这：

```go
func NewEngine() *gin.Engine {
	if config.GlobalConfig == nil {
		config.LoadConfig()
	}

	r := gin.New()
	r.Use(gin.Logger())
	r.Use(gin.Recovery())
	r.Use(middleware.CorsMiddleware())

	uploadBase := config.GlobalConfig.Storage.UploadDir
	if uploadBase == "" {
		uploadBase = "./storage/uploads"
	}
	r.Static("/uploads", uploadBase)

	db := config.ConnectMysql()
	rdb := config.InitRedis()
	c := cache.New(rdb)

	if err := db.AutoMigrate(
		&model.User{}, &model.Event{}, &model.News{}, &model.Resource{},
		&model.Favorite{}, &model.Showcase{}, &model.Admin{},
		&model.DownloadLog{}, &model.Comment{}, &model.CommentLike{},
		&model.ChatMessage{}, &model.ChatPresence{}, &model.DailyMetric{},
	); err != nil {
		slog.Error("数据库迁移失败", "err", err)
		panic(err)
	}

	adminInitSvc := service.NewAdminService(db, rdb)
	if err := adminInitSvc.EnsureDefaultAdmin(); err != nil {
		slog.Warn("创建默认管理员失败", "err", err)
	}

	seedSvc := service.NewSeedService(db)
	seedSvc.AutoSeed()

	registerPublicRoutes(r, db, rdb, c)
	registerAuthRoutes(r, db, rdb, c)
	registerAdminRoutes(r, db, rdb, c)

	return r
}

func Addr() string {
	return ":" + config.GlobalConfig.App.Port
}
```

**关键点**：
- 中间件顺序：`gin.Logger()`（请求日志）→ `gin.Recovery()`（panic 恢复）→ `CorsMiddleware()`
- `/uploads` 静态目录直接由 Gin 托管，上传的文件可通过 `/uploads/xxx` 访问
- 启动时完成三件事：`AutoMigrate` 建表、`EnsureDefaultAdmin` 创建默认管理员、`AutoSeed` 注入测试数据
- 三组路由分别注册：公开 / 会员（需 JWT）/ 后台（需管理员 JWT）

## Step 06：中间件

**文件**：`internal/middleware/cors.go`、`internal/middleware/ratelimit.go`

CORS 中间件：

```go
func CorsMiddleware() gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Header("Access-Control-Allow-Origin", "*")
		c.Header("Access-Control-Allow-Methods", "GET, POST, PUT, PATCH, DELETE, OPTIONS")
		c.Header("Access-Control-Allow-Headers", "Origin, Content-Type, Accept, Authorization, X-Requested-With")
		c.Header("Access-Control-Expose-Headers", "Content-Length, Content-Disposition")
		c.Header("Access-Control-Allow-Credentials", "true")
		c.Header("Access-Control-Max-Age", "86400")

		if c.Request.Method == "OPTIONS" {
			c.AbortWithStatus(204)
			return
		}
		c.Next()
	}
}
```

限流中间件基于 Redis 固定窗口，按 `路由 + 客户端 IP` 计数：

```go
func RateLimitMiddleware(rdb *redis.Client, limit int, window time.Duration) gin.HandlerFunc {
	return func(c *gin.Context) {
		if rdb == nil {
			c.Next()
			return
		}
		route := c.FullPath()
		if route == "" {
			route = c.Request.URL.Path
		}
		key := fmt.Sprintf("ratelimit:%s:%s", route, c.ClientIP())
		ctx := c.Request.Context()

		count, err := rdb.Incr(ctx, key).Result()
		if err != nil {
			c.Next() // Redis 暂不可用时不阻断请求
			return
		}
		if count == 1 {
			rdb.Expire(ctx, key, window)
		}
		if count > int64(limit) {
			c.AbortWithStatusJSON(http.StatusTooManyRequests, gin.H{
				"code": 429, "msg": "请求过于频繁，请稍后再试",
			})
			return
		}
		c.Next()
	}
}
```

**使用场景**：登录/注册接口加了 `RateLimitMiddleware(rdb, 10, time.Minute)`（每分钟 10 次），后台登录是 20 次/分钟。
